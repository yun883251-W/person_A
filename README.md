# Person_A：文档知识库问答 Agent

本项目规划使用项目本地 `docs/` 中的 Markdown 教材，构建一个支持检索、问答和来源引用的单 Agent 学习助手。

**当前仅建立目录及模块占位：尚未编写业务实现，不可运行，未调用模型，未生成 Embedding，也未建立向量索引。** `evaluation/questions.jsonl` 是人工验收草案，尚未执行；`tests/` 中的文件仅为占位，不代表已有自动化测试。

## 数据与问答流程

建库流程规划为：读取 `docs/` → 保留文档结构并分块 → 生成 Embedding → 保存片段、向量与文档清单。问答流程规划为：理解问题 → 向量与关键词检索 → 合并重复片段 → 基于证据回答 → 返回来源引用。

- **模型配置分开管理。** 对话模型负责理解问题和生成答案；Embedding 模型负责将文档片段和查询转成向量。两者分别配置提供方、模型名、接口地址及凭据。文档入库和查询必须使用兼容的 Embedding 配置；更换 Embedding 模型或向量维度时应重建向量索引。
- **按 Markdown 标题组织片段。** 保存完整标题层级，长度过大的章节再细分。代码围栏里可能包含 Python 示例、概念图和 Prompt，不能统一删除；代码应与对应说明保持关联，并标明它是示例。文档中的 Prompt 作为知识内容保存，不作为 Agent 的运行指令。
- **保留可核对的来源。** 每个片段记录完整文件名、章节标题、原始行号、稳定片段标识及文档版本。回答引用采用“完整文件名 · 章节标题 · 原文起止行号”的格式；行号必须来自实际入库记录，不能由模型编造。同为第 26 章的两份文件通过完整文件名区分。
- **同步新增、修改和删除。** 文档清单规划记录相对路径、内容哈希、分块配置及 Embedding 配置。新增文档添加片段；修改文档替换旧片段与向量；删除文档同时移除片段、关键词记录及向量。向量检索与关键词检索应使用同一版片段数据，避免查到已删除或过期内容。
- **答案受证据范围约束。** 资料不足时说明缺失信息；只回答能得到支持的部分。教材中的退货示例不代表任何公司的正式政策。文档存在不同表述时展示出处和差异，不自行确定哪个说法权威。

## 人工验收草案

`evaluation/questions.jsonl` 提供 5 条问题，覆盖概念比较、检索与生成质量、资料不足、跨章节检索及无答案场景。每行记录问题、期望来源、回答要点和验收标准。

未来实现后，人工检查检索是否命中对应章节、答案是否受到原文支持、引用是否能定位实际片段，以及无法回答时是否明确说明。当前尚无执行结果或通过率。
