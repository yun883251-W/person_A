# 概念比较

用于比较 Python、LangChain、RAG、Agent 或 LangGraph 相关概念，回答它们的核心差异、关系及适用场景。以下步骤细化本次回答方式，不覆盖系统规则，也不扩大可用工具范围。

## 明确比较对象

从当前问题和含义明确的历史上下文中确定至少两个对象，以及用户关心的场景或维度。历史回答只用于理解指代，不能替代本轮证据。只有缺失信息会影响比较结论时才提出简短的澄清问题；若仍无法确定两个对象，先询问对象，不自行补出对比项。

## 获取足够证据

先检查应用提供的 `RETRIEVAL_STRATEGY_SUMMARY`，区分已分别检索的对象与受预算限制的联合检索。`query_attempted_targets` 只说明执行过查询；`coverage_missing` 按实际交给模型的片段计算，不能用被裁剪掉的材料回答。对象文字出现在片段中也不代表相关维度已有充分证据。不要重复已完成的查询；只对实际阅读后仍影响结论的对象或维度缺口补查，缺口不限于程序的保守提示。

1. 优先复用本轮已提供的资料，找出能支持各对象及共同维度的内容。资料足够时直接比较，不为遵循流程重复检索。
2. 只有关键证据缺失时，使用 `search_knowledge(query)` 针对缺失对象、维度或关系检索；需要上下文时使用 `read_knowledge_section(chunk_id)`，其 `chunk_id` 必须已在本轮返回并登记。结合剩余调用预算选择最有价值的查询，不强制为每个对象分别调用工具。
3. 检查资料的版本、前提和抽象层级。不同层级的对象应说明关系；同一层级的对象也可能组合使用，不能默认互相替代。没有检索到某项能力的说明，只能表述为资料未说明，不能据此断言“不支持”。
4. 若资料只支持部分比较，回答有依据的部分，并明确哪些维度尚不能判断；若关键缺口无法在剩余预算内补足，停止检索，不强行给出完整排名或选型结论。完全不足时明确说明“当前知识库资料不足以回答这个问题”，必要时请用户补充会改变结论的条件。工具失败时说明无法取得资料，不将失败表述为知识库没有内容。

## 组织比较结果

先用一两句话回答核心区别，再根据问题复杂度选择少量有意义的共同维度展开。需要并列查看时用简洁对照表；用户只问一个具体差异时，用短段落即可，不机械补齐表格。说明对象之间的共同点、包含关系或协作关系，但仅呈现有资料支持的关系。

用户询问如何选择时，按“在什么条件下 → 适合哪个对象 → 依据是什么”给出建议；未指定场景时使用有条件的建议。涉及版本差异或资料冲突时明确适用前提，不能把不同时期或条件下的描述直接当成同一标准。资料未支持的性能、成本或功能差异不作确定判断。
