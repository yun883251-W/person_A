# 会话业务意图与状态接入清单

## 当前状态与一期范围

**一期开发接入已完成。** 契约、状态转换、统一决策入口、SQLite 持久化、B 站跨轮补参、生命周期及公开投影已经接入。开发完成不等于真实模型与真实浏览器联调完成；验收状态见文末。

目标是在已有知识问答、B 站搜索、MBTI 和单轮多任务能力上，统一处理“新任务、继续当前任务、取消、闲聊、需要澄清”。2026-10-18 已合并原 `agent/intent.py` 与会话解析入口：旧路径保留兼容导出，实际规则和分类策略集中到 `agent/dialogue/`。本轮只开发和文本审阅，未运行测试、导入检查、服务或模型联调。

一期每个会话只有一个当前业务焦点，以及至多一个等待补充参数的任务。MBTI 仍使用现有测试快照，通用状态仅关联 `test_id`。知识追问、补充 B 站搜索主题、继续 MBTI 作答的含义不同，不能统一解释为“重新执行上一轮”。

多任务使用 `execution_mode` 表达，沿用现有 planner 的顺序和依赖规则；不把 `complex` 当成业务类型，也不新增语义不明的 `order` 字段。已保存的计划结果只是历史记录，不能恢复执行。一期不实现多任务跨轮恢复、运行中中断、请求 ID 协议、断线恢复或完整任务工作流引擎。

## 新目录职责

```text
src/knowledge_agent/agent/dialogue/
├─ __init__.py        # 模块边界与职责
├─ intent_types.py    # 分类结果、类别和能力快照的共享类型
├─ rules.py           # 确定性规则、知识追问和工具匹配
├─ classifier.py      # 统一 rules/hybrid 选择、JSON 校验和失败降级
├─ contracts.py       # 会话决策、业务状态、参数来源和公开投影
├─ resolver.py        # 生命周期、待补参数和最终会话决策
├─ transitions.py     # 纯状态转换、修订号和派发状态
└─ browser_dispatch.py # 已确认搜索的来源校验、一次派发及结果核对
```

`resolver/rules/classifier/transitions` 不执行 MCP，也不直接写数据库；`browser_dispatch` 是独立执行边界，通过注入的注册器和存储回调派发。MBTI 计分仍由原模块负责。`IntentProposal` 解析契约保留兼容，但运行链路不再启动第二个会话分类模型。

### 2026-10-18 合并与补参修复

原故障有两处：一是“帮我在B站找点视频”没有命中确定性的缺少主题规则，语义澄清没有创建待补任务；二是短回复先经过旧模型分类，后续补参又依赖 `default_knowledge` 原因码，导致“火影忍者”掉进知识检索。

现在 `runner.ask → resolver → rules → 待补参数 → classifier → DialogueDecision → router/执行器` 共用一条入口。生命周期和明确多任务仍由程序识别；已确认的搜索待办先接收具体主题，随后才考虑普通语义分类。最终决定保存实际接受的检索词、回复类别和来源，不再携带能够反向覆盖它的旧分类结果。

`INTENT_MODE` 管通用候选，`BROWSER_INTENT_MODE` 管浏览器候选。规则明确时不调用分类模型，同一输入不会串行调用两个分类器。取消、新任务、MBTI 和知识咨询不当成搜索主题；含糊的“随便”“视频”继续澄清。手动知识 Skill 冲突时不提交新待办或调用浏览器。

已确认的会话搜索由 `browser_dispatch` 校验原始请求、参数来源、会话、轮次、修订号和注册工具后执行；它复用浏览器结果契约，只有工具身份、关键词、固定 URL、动作等均一致才报告打开请求成功。外层 MCP 调用成功但结果不合法时，报告未确认，不回退重放。

已同步原有离线用例的分类契约和浏览器假结果，并补充待办优先于 hybrid 分类的回归用例；本轮未执行。待统一验收场景：

| 同一会话中的输入 | 预期行为 |
| --- | --- |
| “帮我在B站找点视频” → “火影忍者” | 第一轮保存缺主题待办，第二轮补参并调用 B 站搜索，不检索知识库 |
| 上述第一轮 → “你好” → “火影忍者” | 闲聊保留待办，具体主题仍可补齐 |
| 上述第一轮 → “随便” → “火影忍者” | 继续要求具体主题，补齐后执行 |
| 上述第一轮 → “取消” → “火影忍者” | 取消后不再以旧待办授权搜索 |
| 上述第一轮 → “解释什么是 RAG” | 转为明确知识问题，不把整句当搜索词 |
| 手动选择知识 Skill → 完整搜索请求 | 提示 Skill 冲突，不派发 |
| 在另一个会话只输入“火影忍者” | 不继承本会话的搜索待办 |
| 工具外层 success，但内部关键词或 URL 不符 | 不报告成功，不自动重试 |

更新代码后需重启后端，并重新发起第一句搜索请求。旧失败轮次若没有保存 pending，仅凭历史里的澄清文本不会自动恢复可执行任务。本轮不调整 SQLite 表结构，不重建已有会话或索引；此前验证结果不代表本轮增量已验证。
