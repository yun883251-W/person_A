# 对话意图与业务状态

Person_A 在知识检索和工具派发之前，先把用户输入解析为受约束的对话决定。该层负责回答三个问题：用户本轮要开始还是继续一项业务、是否需要补充参数、系统是否拥有执行所需的明确授权。

## 决策模型

对话意图分为：

- `new_business`：开始新的知识问答、MBTI 或浏览器搜索。
- `continue_business`：补全当前待处理任务或继续测评。
- `cancel_business` / `pause_business` / `resume_business`：操作当前唯一业务焦点。
- `chitchat`：不改变待处理任务的闲聊。
- `unclear`：信息不足，需要澄清。
- `unsupported`：能力或工具不可用。

业务类型包括知识问答、MBTI、B 站搜索和通用 MCP 工具。执行模式为单步或最多 3 步的计划。

## 状态约束

每个会话最多保存一个 `focus` 和一个 `pending`：

- `focus` 表示当前业务及其阶段。
- `pending` 只保存下一次继续所需的最小字段，不保存多个隐式任务。
- 明确的新任务替换旧待办；闲聊不清除待办；取消后不会撤销已经完成的外部操作。
- 所有状态都带 revision，写入使用 compare-and-set，拒绝旧快照覆盖新状态。

回答、对话决定和下一业务状态在同一 SQLite 事务中提交。浏览器任务在外部派发前先持久化为已消费状态，避免断连恢复后通过“继续”重复执行。

## 规则与模型的边界

确定性规则优先处理问候、范围询问、明确工具请求、MBTI 控制词、取消/继续和已知补参。仅当规则无法区分且配置允许时，语义分类器才消耗一次模型预算。

模型输出必须通过严格结构校验：

- 不能新增当前输入中不存在的搜索主题。
- 不能选择宿主未公开的工具。
- 不能绕过参数 schema、调用预算或业务状态 revision。
- 分类失败时回退到澄清或安全的知识路线，不授予外部操作权限。

## B 站补参示例

```text
用户：帮我在 B 站找点视频
系统：你想搜索什么主题或作品？
用户：Python 装饰器
```

第二条输入只在同一会话、同一待办 revision 下解释为搜索主题。主题值、原始输入、会话 ID 和来源轮次一起绑定；跨会话、已取消、已消费或过期的补充均会被拒绝。

## 公开投影

API 只返回可展示的业务类型、阶段、缺失字段和 revision，不返回内部授权文本、槽位来源细节或数据库原始 JSON。前端使用该投影恢复界面状态，执行端始终重新读取服务端可信状态。
