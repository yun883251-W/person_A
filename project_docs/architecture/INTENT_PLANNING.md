# 意图边界与多步骤任务规划

系统将咨询类请求和外部操作分开处理。知识解释、概念比较和代码分析进入 RAG；明确的 MBTI 或 B 站请求进入对应 MCP 能力；多个动作组成的输入进入受限计划。

## 计划约束

- 每轮最多 3 个步骤。
- 步骤类型仅为知识问答或当前已公开的 MCP 能力。
- 所有步骤共享模型、工具和上下文预算。
- 依赖关系必须指向前序步骤，循环或未知依赖会被拒绝。
- 工具权限从原始用户从句推导，规划器不能通过改写目标创造授权。
- 一个步骤失败时，无依赖且预算充足的步骤仍可继续；依赖该步骤的任务标记为跳过。

## 示例

```text
先解释 Python 装饰器，再在 B 站搜索 Python 装饰器教程。
```

该输入会形成一个知识步骤和一个浏览器步骤。两个步骤主题均可追溯到原始输入；最终结果包含步骤状态、调用次数、证据和停止原因。

```text
先解释 RAG，再比较它和微调。
```

如果规则能唯一绑定指代主题，则第二步依赖第一步；存在多个候选主题时，系统要求用户澄清。

## 结果状态

计划摘要使用 `completed`、`partial`、`failed` 或 `needs_clarification`。页面逐步展示 `success`、`insufficient_evidence`、`service_error`、`limit_reached` 与 `skipped`，不会把未执行步骤显示为成功。
