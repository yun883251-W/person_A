# 并发模型

HTTP 服务使用进程内有界调度，目标是在不破坏 SQLite 会话语义和模型预算的前提下，让不同会话并行处理。

## 调度规则

- 不同会话可进入独立工作通道。
- 同一会话的问答和写操作按序执行。
- 知识库构建、更新等管理写操作独占相关资源。
- 会话读取使用独立线程和短连接，不共享 SQLite connection。
- 模型与工具分别有并发上限、排队上限和超时。

服务状态通过 `/concurrency` 暴露，只包含配置和计数，不包含用户输入或模型正文。

## 失败与关闭

队列已满、排队超时、同会话冲突和全局管理冲突映射为明确的 409/503 业务错误。模型超时映射为 504。客户端取消等待不代表后台线程已停止；系统继续维持真实 busy 状态，直到工作完成或超时收尾。

服务关闭时停止接收新任务，等待在途任务清理并关闭 MCP 与数据库资源。部署使用 `--workers 1`；多进程共享协调不属于当前运行模型。

项目包含纯聊天突发负载脚本，可通过 `scripts/load_test_api.py` 对指定服务执行受控压测。
