# 聊天模式与会话记忆

当前实现说明。以下功能已开发，尚未运行本轮测试、数据库迁移或模型联调。

## 独立聊天与对话模式

输入框新增“自动 / 知识库 / 普通聊天”。JSON和SSE请求均接受 `response_mode: auto|knowledge|chat`，默认auto兼容原客户端。显式聊天不检索、不绑定任何工具、不使用Skill、不进行知识引用校验；显式知识库只进入知识回答，不执行浏览器/MBTI/多任务操作。MBTI快捷按钮仍发送auto。聊天使用当前配置的聊天模型，没有新增模型依赖。

自动模式先保留既有工具、规划和待补参判断，再对知识/问候/范围外分支做chat/knowledge补充分流。明确闲聊和重述表达直接处理；模糊表达在 `SEMANTIC_ASSIST_MODE=hybrid` 时通过有界JSON分类器判断，失败保守保留原分支。分类计入当前模型调用预算并预留一次回答调用。手动Skill和待补参任务不进入自动聊天分流。已有计划步骤仍只有knowledge/mcp，不自动将缺证据步骤降级为聊天。

聊天上下文包含画像、旧摘要、近期公开问答（包括公开工具结果，但排除测评快照轮次）；不重放原始工具消息或检索载荷。超出预算时先省略画像，再按完整问答对移除较早历史，最后省略摘要；当前问题不截断。保存时只提交本轮问题和最终回答，不复制注入上下文。

知识问答会额外使用最近两轮中的聊天背景，历史引用标记仍被移除；知识回答的证据只能来自本轮检索。旧轮次摘要现在纳入成功的普通聊天，仍排除MCP、测评和多任务结果。聊天不会改变待办或测评状态，历史也不构成操作授权。

前端与Trace显示chat路由及“普通聊天 · 未检索知识库”，避免把模型回答标成有文档依据。仍是阶段进度流加完整回答，不是Token流式输出。chat 路由本身无需迁移；会话记忆遗忘边界需要 schema v4。新增 chat 路由已纳入API和SQLite结果反序列化白名单。

待验证（未执行）：普通聊天→追问；知识问答→“换个生活化比喻”→切回知识库；新会话隔离；重启恢复；长聊天摘要；聊天中请求打开浏览器不得执行；待补参中切聊天不消费待办；旧记录兼容；JSON与SSE模式一致；极小上下文预算和模型异常。
### 会话记忆预算与观测

聊天和知识问答共用 `session/context.py` 的可选记忆预算管理。当前问题、
系统约束和计划依赖不会被该模块移除。上下文超限时依次移除画像、完整历史
问答和会话摘要，知识问答最后才缩减本轮检索证据，仍按完整片段和当前来源 ID 校验。
历史裁剪优先保留最近两轮；更早轮次按当前问题与历史问题的词面重合程度淘汰，
同分时先淘汰更早轮次。该策略只在超预算时工作，不是向量记忆检索，也不增加模型调用。

前端“执行详情 → 组装会话记忆”显示实际注入的历史轮数、预算裁剪轮数、
摘要字符数和历史背景字符数。字符统计含包装；背景统计不含画像，画像字段数
仍在“加载学习画像”中显示。计划上下文作为不可丢弃的整体计入背景字符数，
内部摘要不单独计数。这些信息随原有 trace 保存；旧 trace 缺少新字段时按空值读取。
原文、凭据、画像内容不会因这些统计写入 trace。

后续摘要按当前主题、已讨论内容、未解决问题组织，合并更正、去除已解决问题，
不再要求摘要器累积长期风格偏好。仍沿用单个 summary 文本和原有覆盖水位；
这是生成提示词约束，不是严格的结构化字段协议，不迁移或重写已保存摘要。
清空画像只清空画像记录，不清空聊天或摘要；若要去除历史中提及的偏好，
应同时删除对应会话或开启新会话。当前请求始终优先于旧背景。

本次仅开发，未运行测试或模型请求。待联调：长对话预算裁剪后本轮仍正常保存；
聊天与知识模式交替追问；计划依赖保持完整；新旧 trace 均可打开；
旧摘要可恢复且新摘要按主题组织。跨会话语义记忆尚未实现；显式画像候选提取见 [画像说明](USER_PROFILE.md)。
### 手动纠错与遗忘会话记忆

页面展开“早期对话摘要”，点击“纠正或清空会话记忆”：

- **保存替换**：编辑应保留的会话背景。保存后，该内容替代原摘要，截至保存时的
  全部旧轮次退出模型历史窗口及后续摘要输入。完整聊天记录仍可在页面查看。
- **清空会话记忆**：同样设置截止轮次，但保存空摘要。后续新对话可继续积累记忆。
- 学习画像、MBTI 状态、待补参数等业务状态单独管理，不随此操作清空。
  需要删除个人偏好时，也要在“我的学习偏好”删除对应字段。这不是物理删除聊天数据。
- 此次是显式编辑界面，不会把自然语言中的“忘记”自动当作删除授权，
  也未实现逐条事实定位删除、跨会话语义召回或自动学习画像。

接口 `GET /sessions/{id}/memory` 返回摘要、版本、当前轮号及遗忘边界；
`POST /sessions/{id}/memory` 接收 `summary`、`expected_turn_no`、
`expected_updated_at`，空 summary 表示清空。摘要沿用凭据与旧引用过滤。
读写之间产生新问答或摘要更新会返回 409，必须重新读取再编辑。写操作与问答
共用串行工作线程；忙时返回 503，不抢占在途回答。保存后释放当前会话缓存，
下次恢复从新边界开始；超时等未知结果要求重新读取，不自动重试写入。

存储 schema 升至 4，初始化时从版本 1/2/3 迁移，新增
`session_memory_boundaries` 表，不改写既有问答。截止轮次同时用于最近历史恢复和
摘要批次读取，避免重启后复活旧记忆；清空历史或删除会话时同步清理边界。
