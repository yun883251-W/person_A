# 语义意图、多任务组合与长对话摘要

本次完成开发与文本审阅，**没有运行测试、语法或导入检查、服务、浏览器、数据库迁移或模型调用**。下列用例是预期行为，不是通过记录。沿用现有 API、CLI、页面、DeepSeek 和 SQLite，不增加依赖。

## 1. B 站意图语义补充

常见表达先走规则；提到 B 站且明确表达当前请求、但未匹配固定句式时，最多调用一次模型分类。分类输出固定 JSON：`{"kind":"search|knowledge|needs_clarification","topic":"原文中的主题或空串"}`。程序检查字段、重复键、主题是否出现在当前输入、是否缺少具体内容；否定、引用示例、假设与咨询不升级为工具操作。

分类模型不执行工具、不生成工具名单。确认搜索后，程序仅授权 `mcp__browser__search_bilibili`，原 MCP 流程再生成 `{"query":"..."}` 并进行双端校验。失败或主题不明确时澄清。观看表达仍只打开搜索结果页，不选集、不播放、不读取搜索结果。

| 输入 | 预期行为 |
| --- | --- |
| 我想在B站看火影忍者 | 规则识别并搜索火影忍者，无额外分类调用 |
| 帮我在B站找点数据结构的视频 | 语义补充识别主题，再打开相关搜索页 |
| 去B站给我找些Python教程 | 语义补充确认当前搜索请求 |
| 帮我在B站找点视频 | 缺少具体主题，要求补充 |
| 不要帮我在B站找Python视频 | 不调用浏览器工具 |
| 如何实现“帮我在B站找点Python视频”这个功能 | 作为咨询处理 |

语义补充面向现有 B 站搜索能力，不自动支持任意网站或操作。

## 2. 自然语言多任务组合

使用“先……再……”或明确编号描述两到三个任务。程序按用户原始子句判断能力，再让模型生成固定结构的计划。模型必须逐项复制原始目标；工具授权绑定对应子句，不能通过改写或调整子句获得额外权限。

工具子句复用现有意图入口，不重复分类。搜索参数只来自该步骤原话，不从摘要、前一步回答或其他步骤补造。继续保持最多三步、共享预算、依赖失败跳过及部分完成提示，不进行无限重试或自动重写计划。

| 输入 | 预期行为 |
| --- | --- |
| 先解释什么是栈，再在B站搜索数据结构 | 知识检索回答，再打开数据结构搜索页 |
| 先解释Python装饰器，再帮我在B站找点Python装饰器的视频 | 知识问答与语义识别后的搜索组合 |
| 先解释RAG，再比较向量检索与关键词检索，最后给出学习步骤 | 最多三个知识步骤，仍需本轮文档证据 |
| 先解释Python装饰器，再帮我在B站找点相关视频 | 要求明确第二步主题，不猜测执行 |
| 先在B站搜索Python，再在B站搜索LangChain | 本轮拒绝重复调用同一工具，要求拆开发送 |
| 先开始MBTI测试，再解释RAG | 要求将有状态的 MBTI 操作单独发送 |

顺序不等于数据依赖：主题已明确的搜索无需依赖解释成功。默认模型预算四次，普通“知识＋搜索”通常需要规划、知识回答、搜索参数生成各一次；未知表达可能额外需要一次语义分类。补查、自动 Skill 模型选择和参数修正也消耗同一预算，复杂请求可能部分完成。

## 3. 长对话摘要

完整历史继续存于 `turns`，新表 `session_summaries` 保存摘要、已处理轮次和对应轮次 ID。初始化代码在事务中支持数据库版本 1 升级到 2；本次没有操作实际数据库。

默认最近六轮仍按原样加载。第七个已提交轮次起，保存问答后整理移出窗口的旧内容，每次最多处理十二轮、最多额外调用一次模型，无新增旧内容时不调用。仅纳入知识问答的公开问题与回答，包括明确说明资料不足的轮次；工具原始消息、执行记录、MBTI 状态和组合计划不纳入摘要，其他轮次跳过并推进处理进度。

摘要是有损背景，用于保留学习目标、偏好与较早话题，不是文档证据、引用或工具授权。新请求与摘要冲突时以新请求为准；恢复会话会加载摘要，清空或删除会话会同步清理。

摘要与问答分别提交；维护失败保留旧摘要和已保存问答。辅助调用不计入回答的 `model_calls`，`KnowledgeAgentApplication.last_memory_update` 单独记录维护状态与调用数。目前在同一工作线程维护，可能增加回答返回前的等待时间。

连续对话用例：

1. 在同一会话输入：`我在学习如何做本地文档问答，偏好先讲原理再给简短 Python 示例。请解释 RAG 的工作流程。`
2. 再提出至少六个明确的知识问题，例如分块、Embedding、相似度、提示词、工具调用和会话存储。只有已保存轮次推进历史窗口。
3. 展开页面上方的“早期对话摘要”，查看已保存内容；刷新只读取数据库，不生成摘要。
4. 输入：`结合我最初的学习目标，解释 LangChain 的 Runnable，并按我之前偏好的方式组织回答。`
5. 预期使用摘要与最近历史理解背景，同时检索 Runnable 的本轮文档证据。摘要未保留的细节不能声称记得。
6. 重启后恢复同一会话可重新加载摘要；清空历史后摘要为空。

只读接口：`GET /sessions/{session_id}/summary`，返回 `session_id`、`summary`、`covered_turn_no`、`updated_at`。尚无摘要时返回空文本和零进度；会话不存在返回 404。

## 配置与代码

新增配置均有默认值，不必覆盖已有 `.env`；调整后重启服务：

```dotenv
BROWSER_INTENT_MODE=hybrid
MEMORY_SUMMARY_ENABLED=true
MEMORY_SUMMARY_MAX_CHARS=2000
MEMORY_SUMMARY_MAX_INPUT_CHARS=16000
MEMORY_SUMMARY_BATCH_TURNS=12
MEMORY_SUMMARY_MAX_TURN_CHARS=3000
```

`BROWSER_INTENT_MODE=rules` 关闭语义补充，与通用 `INTENT_MODE` 独立。`MEMORY_SUMMARY_ENABLED=false` 关闭摘要维护与回答中的摘要加载；已有摘要不删除，仍可只读查看。

主要文件：`agent/browser_actions.py`、`agent/semantic_intent.py`、`agent/intent.py`、`agent/planner.py`、`agent/plan_executor.py`、`agent/runner.py`、`agent/memory.py`、`application.py`、`session_store.py`。配置在 `config.py` 和根目录 `.env.example`，摘要接口与页面在 `http/`、`web/`。
