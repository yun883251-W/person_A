# 会话业务意图与状态接入清单

## 当前状态与一期范围

**以下全部属于待开发计划，尚未实现或接入。** 新文件及 TODO 的存在不代表功能可用；本次只创建说明和骨架，不运行测试、导入验证、服务或模型。

目标是在已有知识问答、B 站搜索、MBTI 和单轮多任务能力上，统一处理“新任务、继续当前任务、取消、闲聊、需要澄清”。现有 `agent/intent.py` 含用户正在进行的修改，后续接入应基于届时的真实代码逐项合并，不覆盖或重建整个文件。

一期每个会话只有一个当前业务焦点，以及至多一个等待补充参数的任务。MBTI 仍使用现有测试快照，通用状态仅关联 `test_id`。知识追问、补充 B 站搜索主题、继续 MBTI 作答的含义不同，不能统一解释为“重新执行上一轮”。

多任务使用 `execution_mode` 表达，沿用现有 planner 的顺序和依赖规则；不把 `complex` 当成业务类型，也不新增语义不明的 `order` 字段。已保存的计划结果只是历史记录，不能恢复执行。一期不实现多任务跨轮恢复、运行中中断、请求 ID 协议、断线恢复或完整任务工作流引擎。

## 新目录职责

```text
src/knowledge_agent/agent/dialogue/
├─ __init__.py       # 模块边界与未来公开入口说明
├─ contracts.py      # C01—C12：意图、业务状态、参数来源及公开投影契约
├─ resolver.py       # R01—R12：结合当前输入与会话状态解析意图
└─ transitions.py    # T01—T12：验证状态转移并生成提交提案
```

具体数据类型与函数目标在对应骨架 TODO 中细化。本目录不直接连接 SQLite、不调用 MCP 工具、不替代 MBTI 计分；状态提案经执行层验证后，由现有存储层提交。

推荐顺序：先完成 C01—C12 的契约，再做 T01—T12 的纯状态转换，最后做 R01—R12 的意图解析；随后接 I01—I08 的执行和存储链路，再接 I09—I12 的展示与说明。V01—V10 留到开发完成后统一进行。

## 集成开发 TODO

- [ ] **I01：接入既有意图识别，统一语义但保留执行边界。**
  - 位置：`agent/intent.py`、新增 `agent/dialogue/contracts.py` 与 `resolver.py`。
  - 区分会话动作 `new_business / continue_business / cancel_business / pause_business / resume_business / chitchat / unclear / unsupported`、业务类型与执行模式；将它们转换为已有路由可接受的决定，不把新枚举直接塞入旧 `IntentKind`。
  - 规则优先识别明确指令，模型只补充无法确定的语义；输入包含经过裁剪的当前焦点和待补参数。模型 JSON 必须校验字段、枚举及语义组合，模型不能指定任意工具或直接写会话状态。
  - 未知、非法或超时输出不能消费 pending，也不能触发工具；仅按既有合法分支降级或澄清。现有其他显式 MCP 请求保持原权限边界，未纳入一期状态的能力不自动获得跨轮继续执行能力。

- [ ] **I02：在 runner 建立唯一会话决策入口。**
  - 位置：`agent/runner.py` 的 `ask()`、`_ask_single()`、`_ask_plan()`。
  - 先取得持久业务状态并解析当前会话动作，再决定直接回复、单任务或现有 planner；避免 `should_plan()` 在状态解释之前抢走“继续、取消、补充参数”。
  - 同一轮只形成一份已校验的决策，向下传递，避免各分支重复分类并得出不同结果；保留当前 Skill 普通、自动、手选模式的约束。
  - 闲聊不消费 pending；明确的新任务替代原待补任务。意图不明确时保留原状态并问清目标，不能把业务切换默认为取消旧 MBTI 测试。

- [ ] **I03：按焦点调整 router 与 MBTI 控制语义。**
  - 位置：`agent/router.py`、`agent/assessment.py`、runner 的 `_ask_assessment()`。
  - 路由仍负责能力可用性、工具白名单、知识引用约定与 MCP 分支隔离；通用意图不能越过这些检查。
  - 裸输入“继续、取消、下一题、5”等只在相应焦点与允许状态下解释为业务控制；不能因为会话曾有测试快照就自动归入 MBTI。
  - 复用已有 `active / paused / ready / completed / cancelled` 状态机，通用状态只关联现有 `test_id`，不重复保存题库、答案或评分结果。已完成测试不能被含糊的“取消”改成已取消。
  - 明确取消的是待补任务还是当前业务。取消仅停止后续业务交互，不撤销已完成浏览器操作，也不宣称中断正在执行的请求。

- [ ] **I06：独立处理工具派发与业务失败后的状态收尾。**

  - 待补参数已齐备且全部执行校验通过后，在调用外部工具前先以独立短事务消费 pending，并记录“进入派发保护、执行结果未确认”；该事务失败则不能调用工具。
